# Current privacy behavior — Bonsai 3.6.9

Local scans, process metrics, preferences and audit records stay on this Mac. Clean classification reads metadata; optional maintenance validation reads preference/list/database contents locally. Update verification reads installer and app bytes locally. These contents are not uploaded or logged.

Updates uses consented public app metadata sources and publisher downloads. The optional Homebrew public catalog is separately gated: supported package names would be sent to formulae.brew.sh; it remains off during this audit pending that consent. Ephemeral HTTP sessions do not store credentials/cookies. Pinned mas may use the existing Apple account through Apple's services; authentication belongs to the user and Apple, not Bonsai. The one-shot authorization helper supplies only local real user/group IDs and a fixed sanitized environment to mas, captures bounded output, and accepts a single validated installed-app bundle ID. It cannot accept a command, password, URL or installer path. No persistent privileged service is installed.

Supported Sparkle full ZIPs install directly in this ad-hoc build: publisher HTTPS downloads, installed Ed25519 keys when declared, exact artifact length/build, strict original-publisher code validation and recoverable atomic replacement. Unsupported archive formats retain handoffs; properly signed builds can include the MIT framework. The public ChatGPT/Codex appcast is pinned to the observed official host and exact installed identity/key. All dependency provenance is in Vendor/Dependencies.json. Fuller historical details below remain relevant except where superseded here.

# Privacy and permissions

Bonsai is local-first. It has no account, telemetry upload, analytics SDK, tracking identifier, update server, or startup network request. File contents are not read for cleanup classification; stat metadata, filenames, directory listings, app/agent plists, system counters, and process metadata provide the UI. A selected app’s normal Bundle plist is read for identity. Temporary scan manifests stay in memory.

Preferences are in macOS UserDefaults for `app.ottercare.mac.nature`. History is `~/Library/Application Support/Otter/history.json` (directory 0700, file 0600), capped to 100 operations. Outcomes abbreviate the home directory, remove control characters, redact common URL credentials/token fields, and cap each command detail. It is still a local record of filenames and operations; delete that file yourself to clear history. File contents are never logged.

Opening Updates automatically checks metadata unless the persistent Automatic setting is off. Turning it off cancels the active pass; app launch alone makes no update request. Schema-versioned results, per-app states and source coverage are cached locally for thirty minutes. Checks contact HTTPS feeds declared by installed apps, Apple's public lookup API (bundle identifier and host locale country), Electron generic/public GitHub release metadata and configured Homebrew repositories. Ephemeral HTTP sessions have no cookie or credential storage; responses are capped at 2 MiB and twelve seconds, with three concurrent requests, up to 128 declared sources, and a 120-second scheduling budget. Remaining in-flight calls have their own bound. Electron flat metadata is capped at 65 KiB; unsupported providers/private repositories/unsafe endpoints are refused. Endpoint validation rejects credentials, non-HTTPS URLs, obvious local hosts and IP literals but does not prove DNS address ownership.

Homebrew catalog refresh is bounded to 120 seconds; fixed installed-cask JSON retrieval to ninety seconds and 2 MiB. Literal local tap definitions are read within three seconds/3,000 nodes/depth five, without symlink traversal or Ruby evaluation. Only literal cask/version/homepage metadata is used; ambiguity or interpolation is refused. No tap trust is granted. Homebrew analytics and implicit refresh are disabled in Bonsai-launched commands. Update buttons use native App Store/publisher handoffs, or explicit Homebrew install review. Opening a source page/app contacts its service; no publisher package is downloaded by metadata discovery. Third-party installers remain publisher-controlled.

Full Disk Access is optional and is granted by the user through System Settings. Bonsai does not request Accessibility, camera, microphone, location, or root filesystem mutation. The explicit Read login items action can ask administrator authorization solely to launch Apple’s sfltool dumpbtm; no caller-supplied command/arguments or persistent privileged helper is accepted. The delivered app parses the bounded response in memory and does not save raw BTM output. A bounded structured current-user snapshot and read timestamp are stored in own UserDefaults so the list survives relaunch; saved entries are marked stale until refreshed. It contains app/service names, paths and reported states, not the raw diagnostic dump. The authorization sheet is controlled by macOS and must be approved or cancelled by the person. Rights are destroyed when the read finishes. Restricted locations are partial/unavailable until access changes. Screen cleaning uses only the app’s own windows/events and does not install a global keyboard interceptor. Process actions are owner-limited.

Privacy manifest declares no data collection/tracking. Required-reason entries cover own preferences, displayed and user-authorized filesystem metadata, displayed disk capacity, and monotonic timer/rate calculations. The manifest and permissions require final publisher review before any store submission. This release targets direct local distribution, not the Mac App Store sandbox.

The optional Trash-app watcher is off by default. If enabled, it inspects immediate .app metadata in the user’s Trash every thirty seconds, then offers leftover review. It never removes files automatically. Full Disk Access may be required. No analysis-report, helper binary, sensor driver or licensing component from the supplied reference is included in the app or source archive.

The saved Otto app uses app.ottocare.mac and ~/Library/Application Support/Otto/history.json. Its preferences/history/permissions remain separate. Neither app migrates settings or automatically grants access. Both audit directories/cache names/own identifier families are protected by the cleanup services.

Expanded Apps inspections remain local. They read declared helper identifiers from the selected app's plist, inspect exact per-user temporary cache paths and may show a uniquely named Application Support candidate with an explicit unproven-name warning. App/cache manifests are memory-only. No content search, background elevation, helper execution or automatic selection of personal support data occurs. Sort direction and system-filter preferences are stored locally; association reports expire after five minutes within the current process.

Pinned Mole protection scripts run locally, without network or deletion, before uninstall inspection/actions and supported user-agent changes. They receive bundle/service identifiers only, not file contents. SHA-256 integrity checks bind their reviewed bytes. General arbitrary-shell execution remains unavailable. See MOLE-BACKEND.md for the actual integration scope. The remaining workflows use native services; no proprietary Mole application/helper/license code is included.

Status 2.11 reads executable paths and parent PIDs alongside existing owner/start-time and usage metadata. These values remain in memory and are shown only locally. It does not collect command arguments, environment variables or file contents. App pins store bundle path and owner in local preferences. Copy PID/name/summary writes to the local clipboard only on an explicit click; process snapshots are not automatically persisted in history or transmitted.

## Bonsai 3.2 access checks

Protected-folder checks read directory metadata only, one entry per Safari/Mail/Messages probe. They do not read private database contents, TCC databases, credentials or file contents. Full Disk Access is a user-managed macOS setting, not an automatic grant. Scans can report metadata from chosen protected folders after permission; cleanup protections and no-elevation policy remain unchanged. Usage-description keys explain folder/volume prompts. All scan state and probes are local. No scan data is transmitted.


## Analyze actions — 3.2.1

Files now open a compact, centered glass dialog showing name, measured size, Reveal in Finder and Move to Trash. One confirmation gives Trash recovery information; no generic review/preview/results sheet intervenes. Folders still drill into the map and expose the same two context actions. Partial sizing does not block moving a known directory itself. DiskTrash moves the explicitly selected root with identity, parent, containment, ownership, protected-path, exclusion and running-app checks; it never recursively deletes or follows child links. Existing Clean/uninstall recursive validation is unchanged. Outcomes and recovery paths remain in local sanitized history. Analyze folder selection now uses SwiftUI’s managed folder importer with a Go to folder path fallback.

Bonsai 3.3 renders bonsai growth from existing measured allocation only. Original Canvas artwork is local and deterministic. A 30-fps timeline runs only for the bounded 1.6-second successful Trash response; its task cancels when the view leaves. Reduce Motion renders the final still state. No network request, filesystem backend change, new permission or external dependency is introduced.
