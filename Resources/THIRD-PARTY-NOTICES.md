# Artwork and dependencies

Bonsai 3.8.0 uses five original AI-assisted bonsai portraits generated with the built-in image-generation tool: cherry blossom for Clean, Chinese elm for Apps, Japanese maple for Optimize, black pine for Analyze and olive for Status. Golden ginkgo is reserved exclusively for the application icon and its navigation/About copies. The transparent PNGs are bundled locally under Trees/. They are artistic botanical interpretations. Exact prompts, creation method, dimensions and SHA-256 are recorded in Trees/Artwork.json. No artwork is generated or downloaded at runtime.

Bonsai 3.3.7 uses an original native bonsai emblem on an ivory tile, rendered by scripts/emblem.swift. This single master supplies the navigation button, application ICNS and About artwork. Source dimensions and SHA-256 are in BonsaiIcon-Artwork.json. No external artwork or new dependency is required for the icon. The video “Spirit Tree” by VISUALDON (https://www.youtube.com/watch?v=DtE5Y5VGkjU) informed the previous 3.0 page circulation, removed in 3.1 at the user’s request. No footage, audio, textures or other video assets are copied or bundled. Palettes use warm ivory, blossom pink, moss green and ceramic tones, with a separate dark appearance.

Bonsai retains the existing installation's data namespace for continuity. The application is based on tw93/Mole behavioral research with an independent native implementation and bundled pinned Mole protection code. GPL-3.0 applies; see LICENSE, NOTICE.md and ProtectionBackend/Provenance.json. Public macOS frameworks require no added package dependencies.

Bonsai 3.6.6 bundles Mole's GPL-3.0 Optimize shell libraries at c430bac637929ebede043df81d3bef319428309c under MaintenanceBackend/. The allowlisted run.sh adapter executes seven upstream handlers. Log destinations are changed to Bonsai's local log directory; generated Finder cache removals are routed through an independent ownership-checked native Trash helper. The original license, complete bundled source and hash manifest are included. Other app functions continue to use native services; this is not a claim that all tasks use Mole CLI.

Bonsai 3.6.8 adds Sparkle 2.10.0 (MIT, https://sparkle-project.org), mas 7.0.0 (MIT, https://github.com/mas-cli/mas), and libarchive 3.8.9 public API headers (BSD-style, copyright Tim Kientzle; implementation supplied by macOS). Sparkle-LICENSE, mas-LICENSE and libarchive-LICENSE are bundled. Download versions and checksums are pinned in Vendor/Dependencies.json. Sparkle verifies publisher updates; mas uses Apple's store services and may need administrator approval and an existing store account. It uses private Apple interfaces and may need updates for future macOS releases. Electron ZIP installation verifies the publisher checksum and installed app's designated signing requirement. Unsupported website installers remain explicit handoffs.

The 3.6.8 Mole adapter also admits old saved-state cleanup, corrupt preference repair, corrupt shared-file-list repair, and login-item audit. Native Trash validation checks ownership, identity, exclusions and running apps. Additional upstream dry-run diagnostics cover privileged networking, permissions and history maintenance. Those checks do not claim to apply repairs. Native services continue to handle Clean, Analyze, telemetry and app inventory; not every Bonsai task invokes Mole CLI.

Read-only Apple Silicon temperature sensor key mappings were checked against the public [Stats sensor catalog](https://github.com/exelban/stats/blob/master/Modules/Sensors/values.swift). Bonsai implements its own bounded AppleSMC reader; it performs no hardware writes.
